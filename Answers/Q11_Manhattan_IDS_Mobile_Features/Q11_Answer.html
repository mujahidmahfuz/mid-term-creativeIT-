Q11. Connectionist vs Reductionist Models, and Manhattan-Distance Iterative Deepening for Mobile Phone Features

Question. Discuss connectionist and reductionist models. Use Manhattan-distance iterative deepening search (Diagram 4) to expand the conceptual space, where every next iteration expands the search space. Apply this to designing the features of a mobile phone, using certain paths for expansion as shown in the figure. Give pseudocode.

1. The idea in plain words

Think of every possible phone as a point on a map, with one axis per feature (camera, battery, screen, AI chip, foldability). Today's phone sits in the middle, like the green dot in Diagram 4. In round 1 we look at every phone that is one small step away. In round 2 we look two steps away, and so on. Each round draws a bigger ring around the start, so each iteration expands the search space. When the rings stop giving better ideas, we do something bolder: we add a new axis to the map (a new feature nobody sells yet). That is expanding the conceptual space, not just searching it.

2. Connectionist vs reductionist models

Reductionist modelConnectionist model
Core ideaBreak the whole into parts, understand each part, then build up the whole ("one part at a time") Meaning comes from the connections between many simple units, like neurons in a network
View of a phoneCamera, battery and screen are judged one by one and the scores are added Features affect each other: camera + AI chip = computational photography, bigger screen drains the battery
CreativityImprove one part at a time (incremental) Find new links and associations between parts (combinational, "everything connects to everything else")
StrengthClear, explainable, easy to testCaptures interactions and the whole system (holism)
WeaknessMisses effects that only appear when parts combineHarder to explain why a result is good

A good design agent uses both. In our model the search moves are reductionist (change one feature by one level), while the evaluation can be connectionist: a learned network that scores how the features work together.

3. Assumptions

  • Each feature has discrete levels 0 to 6 (foldable 0 to 2). Today's phone is (camera 3, battery 3, screen 3, AI 2, fold 0).
  • One action = raise or lower one feature by one level. So the cost between two designs is their Manhattan distance, |Δcamera| + |Δbattery| + …
  • Creative score = 0.75 × utility + 0.25 × novelty. Utility has diminishing returns (too much of a feature costs heat, weight and price). Novelty = distance to the closest phone already on the market (5 known phones).
  • Stop expanding when two rings in a row fail to beat the best score by at least 1 point (a plateau).

4. Mapping the search to phone design

5. Step-by-step approach

  1. Encode today's phone as S0 and set d = 0.
  2. Run a depth-limited DFS that never leaves the Manhattan ball of radius d around S0.
  3. Score the outer ring (distance exactly d) and keep its best design.
  4. If the ring beats the best so far by ≥ 1 point, accept it. Otherwise count a "stale" ring.
  5. If two rings in a row are stale, the space is used up (plateau). Otherwise set d = d + 1 and repeat, which expands the search space.
  6. At a plateau, expand the conceptual space: add a new feature axis and restart the rings from S0.

6. Pseudocode

function ManhattanIDS(S0, dims, score):
    best ← S0;  stale ← 0
    for d = 0, 1, 2, ...:                               # each iteration = a bigger ring
        BALL ← DLS(S0, limit = d, dims)                # all s with |s - S0|_1 ≤ d
        RING ← { s in BALL : |s - S0|_1 = d }
        if RING is empty: break                       # whole space covered
        top ← argmax score(s) over RING
        if score(top) ≥ score(best) + 1: best ← top;  stale ← 0
        else: stale ← stale + 1
        if stale = 2: break                           # plateau: rings stopped paying off
    return best

function DLS(S0, limit, dims):                   # depth-limited DFS inside the ball
    STACK ← [S0];  SEEN ← {S0}
    while STACK not empty:
        s ← STACK.pop()
        for each feature i in dims, step in {-1, +1}:
            n ← s with feature i changed by step
            if n valid and n not in SEEN and |n - S0|_1 ≤ limit: SEEN.add(n); STACK.push(n)
    return SEEN

# creative outer loop
best5 ← ManhattanIDS(S0, 5 features)
if plateau: add "health_sensor" axis;  best6 ← ManhattanIDS(S0 + (0), 6 features)

8. Using certain paths for expansion (the red arrow)

Exploring every ring in every direction is expensive. Diagram 4's red arrow suggests following a preferred path. We let only camera, screen and AI change (a "camera + smart features" strategy). The real run shows the trade-off:

Expansion strategyBest designScoreStates generated
Full rings, all 5 features(4, 4, 3, 5, 2)88.416150
Guided path (camera + screen + AI)(4, 3, 4, 4, 0)81.4652 (4% of the work)

The guided path is about 25 times cheaper but misses ideas on the battery and foldable axes. A practical plan is to use guided paths for quick ideas, then full rings around the most promising area.

9. Expanding the conceptual space

Searching inside the same five features hits a plateau at 88.4. So we change the space itself and add a new dimension: an IoT health sensor (levels 0 to 3). No phone on the market has it, so it brings both usefulness and novelty. Re-running the rings in 6 dimensions finds (5, 5, 3, 5, 1, 3) with score 99.3, a jump of +10.9 that no amount of extra searching in the old space could reach. In course terms, adding a sensor modality changes the space, not merely the data. It is the closest thing to transformational creativity in Boden's sense.

11. Summary

Reductionist thinking changes one feature at a time. Connectionist thinking looks at how features work together, and a good design agent uses both. Manhattan-distance IDS grows the search space ring by ring around today's phone, keeping memory small and finding the nearest good ideas first. Preferred paths (the red arrow) cut the cost by 96%. When the rings stop paying off, adding a new feature dimension expands the conceptual space and gives the real creative jump (88.4 → 99.3).
