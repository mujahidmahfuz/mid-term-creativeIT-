Q5. Heuristic vs Non-Heuristic Search, and Simulated Annealing for Product Recommendation

Question. Discuss heuristic and non-heuristic search approaches. In product recommendation you want to use the simulated annealing (SA) search algorithm to recommend products. How will you use it? Explain in detail with an example.

1. The idea in plain words

A recommender has to pick a few products, a "slate", from a big catalogue. Trying every slate is too slow, so we search. Plain hill climbing only accepts changes that make the slate better, so it gets stuck on the first good-looking slate. Simulated annealing behaves like a curious shopper: early on (when it is "hot") it sometimes accepts a worse slate just to look around. As it "cools down" it becomes picky and settles on the best slate it found.

2. Heuristic vs non-heuristic search

Non-heuristic (uninformed, blind) search uses only the problem definition: start, actions and goal test. It has no idea which direction is "warmer". Heuristic (informed) search also uses a function h(n) or a score that estimates how good or how close a state is, so it can try promising states first.

For recommendations the "path" does not matter; only the final slate does. That makes local search (hill climbing, SA) a natural fit: it keeps one slate in memory and keeps improving it.

3. Assumptions

  • A catalogue of 16 products in 9 categories. Each product has an interest vector (audio, fitness, photo, work) and a popularity value.
  • One user who likes audio, fitness and photography, and who has been browsing phones all week.
  • We show a slate of k = 3 products. That gives C(16,3) = 560 possible slates, small enough to check the true best by brute force.

5. How to use SA in a recommender (step by step)

  1. Build the starting slate from what the user already looks at (here, their 3 most-viewed phones).
  2. Set a high starting temperature. This is the exploring phase.
  3. Make a random neighbour: swap one product.
  4. If the new slate scores higher, keep it. If it scores lower, keep it anyway with probability eΔ/T.
  5. Cool down (T ← αT) and repeat. Remember the best slate seen so far.
  6. When T is tiny, show the best slate. Re-run it every session, because the user's history changes.

6. Pseudocode

function SA_Recommend(start_slate, T0 = 0.10, alpha = 0.97, iters = 250):
    current ← start_slate;  best ← current;  T ← T0
    for it = 1 to iters:
        out ← random product in current
        inn ← random product not in current
        candidate ← current with out replaced by inn         # neighbour
        delta ← score(candidate) − score(current)
        if delta > 0 or random() < e^(delta / T):          # worse moves allowed while hot
            current ← candidate
        if score(current) > score(best): best ← current
        T ← alpha × T                                     # gradual cooling
    return best

7. Worked example (real run)

Hill climbing gets stuck on "all phones"

The start slate is Phone Pro X, Phone Max, Phone Lite with score 0.961. Hill climbing makes one good swap (Phone Max → Phone Mini, score 1.007) and then stops. Every single swap from there is worse. Taking out one phone loses a lot of relevance, and with only two categories there is no variety bonus yet. This is a local maximum: a "same-category" bubble.

8. Why SA suits recommendation

  • It breaks the filter bubble. Pure "more of the same" (hill climbing on relevance) keeps showing phones. SA's early worse moves bring in serendipity: the camera, the tablet.
  • Slow to heat and gradual cooling. This is the course's choice principle: introduce the best choice gradually and keep it warm. A hot start explores, slow cooling exploits, and the final slate is stable.
  • It is cheap. Only one slate is kept in memory, and each step scores a single swap. It is easy to run per user, per session.
  • Tuning matters. If T0 is too low, SA behaves like hill climbing. If cooling is too fast, it freezes early (2 of our 30 runs still missed the optimum). Random restarts or a slower α fix this.

10. Summary

Non-heuristic search explores blindly. Heuristic search uses a score to head for good states. For recommendations we only care about the final slate, so local search fits. Hill climbing got trapped on an all-phones slate (1.007). Simulated annealing accepted a worse slate early (p = 0.56), escaped, and found the true best slate (1.084) in 28 of 30 runs. It mixes relevance with novelty and variety, which is exactly the creative balance a good recommender needs.
